# Spec: ai-coding-adoption-playbook

## Goal

A practical kit for rolling out an AI coding tool across an engineering organization, with Cursor as the working example. It gives a deployment or customer success manager the method, the measures and the templates to go from licenses bought to regular use.

## Audience

- A deployment manager or customer success manager running a rollout.
- An engineering leader who owns the outcome and has to report on it.
- A champion inside a team who is asked to help colleagues.

## Non-goals

- No employer data, no customer names, no screenshots of internal tools.
- No claims about results. Every number in this repo is a definition, a formula or synthetic sample data.
- Not a product guide. Anything that depends on product behavior is marked "verify against current Cursor docs".

## What is in it

- `docs/` has five short guides (align, enable, embed, measure, expand) and a simulated worked example.
- `docs/templates/` has four fill-in templates: a decision review, a champion charter, a 30-60-90 plan with decision gates, and a security and data checklist.
- `.cursor/rules/` has two small example rules.
- `tools/adoption_scorecard/` is a small Python tool that turns a usage CSV into a Markdown adoption report.
- `data/sample_usage.csv` is synthetic, generated by a seeded script.

## Acceptance criteria

1. Each guide opens with one paragraph on its purpose, contains a checklist, and marks product-dependent statements with "verify against current Cursor docs".
2. Nothing in the repo is employer data, a real customer, a real person, or an invented statistic. All sample data is labeled synthetic.
3. `docs/04-measure.md` defines four metrics (licensed, activated, weekly active, sustained). For each it says how the metric can be inflated and which companion metric exposes it.
4. `python tools/adoption_scorecard data/sample_usage.csv` prints the report, and `pytest` passes with at least 12 tests.
5. No em dashes, no en dashes, no emojis, and none of the banned words appear in any file. `python tools/check_style.py` checks this and passes.

## Scorecard report sections

1. Funnel: licensed, activated, weekly active, sustained.
2. By team: sustained rate, trend flag, median active days.
3. Depth: users with agent sessions versus completions only.
4. Status panel: each signal on its own, with no composite score. Flags to investigate. Depth is reported separately and is not scored.
5. What each metric can hide, and what to check it against.
